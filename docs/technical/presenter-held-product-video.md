# 人物持物口播：手拿商品图与视频衔接

日期：2026-11-18。需求与差距见 `../requirements/presenter-digital-human-gap.md`（§10 为落地记录）。

## 流程

```text
1 出镜人物（上传 / AI 生成，露双手）
2 商品参考图 1–3 张
3 手拿商品图（改图模型：人物第 1 张 + 商品图 → 候选，人工选用）
4 口播台词（时长×4 字）
5 生成设置（默认 8 秒、1080P、9:16）
→ 创建口播分镜 → 合成配音 → 生成本镜
```

## 接口

`POST /api/creation/projects/:id/presenter-held-image`（运营角色；与其他创作写接口一样需要 CSRF 与 If-Match）

| 字段 | 说明 |
| --- | --- |
| `personAssetId` | 人物图素材编号，改图的第 1 张参考图 |
| `productAssetIds` | 1–3 张商品图 |
| `holdPrompt` | `chest` / `side` / `both` / `custom`；服务端按 key 取模板 |
| `extra` | 补充说明，≤500 字；`custom` 时必填 |

服务端创建「人物 + 商品」图片输入节点、一个 `edit` 节点（`presenterHeld:true`，`size 1024x1536`）和对应连线，随后走既有 `preview → start`；预览不可启动时回滚刚建的节点。结果素材标记 `derivedFrom.kind='presenter-held'`，向导据此把它从商品图列表中分出来。每次调用只产生 1 张候选。

## 创建分镜时的衔接

`POST …/presenter` 新增 `holdAssetId`。有持物图时：

- 视频节点只引用这张图，不再连商品图；`presenterAssetId` 记为持物图。
- 一律 `videoMode=frames`，持物图接 `first`（首帧）；`dubMode` 强制 `post`，`ratio` 强制 `adaptive`（跟随持物图）。向导里这两项锁定并显示说明。
- 真实口型不再用 H3 参考音频，改为生成后在「本镜预览」点「只改嘴」（阿里云 VideoRetalk / 可灵）。
- 提示词用 `buildPresenterPrompt({holdTag})`：以该图为唯一依据，固定机位，手和商品静止，仅呼吸、眨眼、轻微头部动作，半身中景，头顶留白，脸、肩、手、商品完整入镜且不被边缘裁切。

### 2026-11-19 修复：视频里脸不完整

现象：本镜预览里人物脸被裁掉一部分。原因有三层，提示词只占一层：

1. **参考模式整幅重绘。** 旧规则只有 `dubMode=post` 才用首帧；默认「口型同步」走 `reference`，H3 只把持物图当参考，会重新取景，常常拉近到脸部被切。改为首帧后，第一帧就是持物图本身，构图被锁住。
2. **比例不一致。** 持物图是 1024×1536 竖图，若分镜比例是 16:9，视频必须裁成横图，头顶和下巴最先被裁。改为 `adaptive` 跟随首帧。
3. **提示词景别偏紧。** 原文「半身中近景、脸占画面高度约三分之一」本身就偏近。持物图、人物定妆照和视频提示词统一改为「半身中景、头顶上方留白、整张脸位于上三分之一且不被边缘裁切、脸约占五分之一高度」。

另外本镜预览框原为固定 16:9 + `object-fit:cover`，会把竖屏视频裁掉上下。改为按视频自身比例 `contain` 显示，避免把“显示裁切”误判成“生成裁切”。

已有的旧分镜节点不会被自动改写；需要重新创建口播分镜，或在画布里把该视频节点改成首帧模式、比例改「自适应」后再生成。

### 2026-11-19 第二轮：人还是偏近镜头

首帧模式已经锁住构图，但 H3 仍会把镜头缓慢推近，且仅写「固定机位」不够。提示词改为几何约束：

- 持物图 / 定妆照：竖构图半身中景、不是特写，机位距人物约 1.5–2 米；人物从头顶到腰部约占画面高度 80%；头顶留白约画面高度 10%；整张脸从额头到下巴完整可见且不被任何边缘裁切。
- 视频（首帧模式）：单独一行「镜头固定不动：不推近、不拉远、不缩放、不摇移、不平移，首帧整幅画面完整保留」；「人物始终停在画面中央，与镜头距离不变，不向镜头走近，不变成特写」；「整张脸全程完整在画面内」。只保留呼吸、眨眼、很小幅度的头部晃动，不转头、不低头、不侧脸。

底片本身拍得近，提示词补不回来：第 3 步的持物图先人工确认脸和头顶完整，再拿去生成视频。时长越长越容易漂移，验证阶段先用 5 秒。

## 默认值

时长默认 8 秒、范围 5–10 秒（`shared/creation-presenter.mjs`）；台词上限 = 时长×4；向导默认 1080P，服务端缺省仍是 768P。

## 验证

`tests/creation-presenter.test.mjs`：提示词预设、持物图提示词、`holdAssetId` 校验、`presenterHeldImage` 节点与连线顺序（人物在前）。未做真实付费调用。

## 只改嘴（可灵对口型）

分镜生成并合成配音后，可在「本镜预览」点「只改嘴」：用成功视频作底片、已合成配音作音频，交给「环节默认 → 对口型」的渠道（默认阿里云 VideoRetalk，备选可灵），结果作为新素材保存。画面其余像素沿用底片，只重画嘴部。细节见 [lipsync-providers.md](lipsync-providers.md)、[kling-channel.md](kling-channel.md)。

## 已知限制

H3 的参考音频口型是整幅重绘，所以有持物图时不再使用；持物图的手指数、商品完整性和脸是否完整只能人工检查，持物图本身脸被裁就应重新生成候选，视频无法补回；首帧模式下 H3 仍可能有轻微镜头漂移，需要真实样片验证。
