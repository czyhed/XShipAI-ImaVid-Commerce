# 2026-11-18 人物口播视频：需求确认与实现记录

状态：v0.1 已实现，等待用户用测试商品验收。2026-11-18 追加「手拿商品图」步骤与 8 秒默认，见 `presenter-digital-human-gap.md` §10；下文 5–8 秒、参考模式一次生成为旧口径。本文记录已对齐的需求、实现边界与验证方法；付费生成不由开发侧执行。

## 目标

在现有商品视频工作台里，生成一条 **5–8 秒、有真人感人物出镜介绍商品** 的视频分镜。

- 人物来源：上传真人照片，或用 AI 生成虚拟人物。
- 视频时长：5 / 6 / 7 / 8 秒，默认 6 秒。
- 输出比例：默认 9:16；也支持 16:9、1:1。
- 分辨率：默认 768P；样片可用 480P；支持 1080P。
- 商品保真：按参考图保持大致外观，不承诺像素级一致。
- 口型同步：先做口型同步（lipsync）与后期配音（post）两条样片，由用户验收后决定默认方式。
- 功能范围：新增「人物口播」入口，不改变现有分镜、文生视频、首尾帧、参考模式与批量生成的默认行为。

## 已确认决策

| 编号 | 主题 | 决定 |
| --- | --- | --- |
| P-01 | 人物来源 | 上传真人照片与 AI 生成虚拟人物都支持；AI 人物用生图节点生成定妆照。 |
| P-02 | 口型同步 | 两种方式都可选：口型同步（TTS 音频作为 H3 参考音频）与后期配音（视频生成后再混音）。先各做一条样片再定默认。 |
| P-03 | 功能入口 | 视频工作台新增「人物口播」弹窗；不改造现有分镜默认流程。 |
| P-04 | 商品保真 | 生成式视频只能做到“大致一致”；以 1–3 张商品参考图约束形状、颜色与包装，不保证文字、logo、纹理完全准确。 |
| P-05 | 台词 | 第一人称中文口语，18–32 字，按每秒约 4 字控制；可用文本模型起草，但只允许使用商品事实。 |
| P-06 | 展示方式 | 手持展示、桌面展示、使用中三种，默认手持展示。 |
| P-07 | 数据归属 | 人物图、商品图、台词与参数都落在画布视频节点上；分镜表只追加一个分镜并指向该节点。 |

## 实现方式

### 数据模型

视频节点新增三个字段：

- `presenterAssetId`：人物参考图的素材编号；用于引用校验与删除保护，并加入 `creation-store` 的引用字段集合。
- `presenterSource`：`upload` | `generated`，仅用于界面说明。
- `presenterStyle`：`handheld` | `tabletop` | `in-use`。

视频节点本身：

- `videoMode: 'reference'`；
- `params: { duration, resolution, ratio }`；
- `dialogue: [{ text, language: 'zh', roleId }]`，默认角色名「主播」；
- `dubMode: 'lipsync' | 'post'`；
- 提示词通过 `{{ref:<节点编号>}}` 引用人物图与商品图，提交时由服务端换算成 `<Picture N>`；
- 台词不写进提示词：口型同步由服务端追加 `<d>[Chinese] …</d>` 与“音色参考 `<Audio N>`”，后期配音只用于 TTS。

### 创建流程

1. 用户打开「人物口播」弹窗。
2. 人物：上传照片，或输入外观描述后点「生成人物图」。
   - 服务端 `POST /api/creation/projects/:id/presenter-image` 创建 `generate` 节点并立即提交生图运行；
   - 生图不可用时删除刚建的节点并返回原因；
   - 运行成功后，弹窗自动把结果素材设为人物参考图。
3. 商品图：从商品创作图、本项目图片中选择 1–3 张，也可现场上传。
4. 台词：手写，或点「AI 起草台词」调用 `POST /api/creation/projects/:id/presenter-script`；只调用文本模型，不合成配音。
5. 设置：时长、展示方式、配音方式、分辨率、比例；显示视频积分预估（不含语音）。
6. 点「创建人物口播」调用 `POST /api/creation/projects/:id/presenter`：
   - 创建人物图输入节点、商品图输入节点、视频节点与 1–4 条 `refImage` 连线；
   - 创建或复用「主播」角色；
   - 追加一个分镜；
   - 只建节点，不提交付费生成。
   返回工作台后自动选中新分镜并展开「台词与配音」，用户不需要自己找入口。
7. 用户在分镜编辑区点「合成配音」，再点「生成本镜」。

### 校验

- 时长必须是 5–8 的整数秒。
- 商品参考图最多 3 张；项目关联商品时至少 1 张。
- 人物图与商品图必须是本工作空间的图片素材（创作素材或生成结果），未删除、未处于删除待处理状态。
- 台词清洗后不能为空；按 `时长 × 4` 个汉字截断。
- 人物图、商品图数量与 H3 参考模式限制一致（参考图合计 ≤ 9，参考素材合计 ≤ 12）。
- 口型同步必须使用参考模式；节点创建时固定为 `reference`。
- 角色最多 20 个；没有「主播」时按系统默认音色 `zh_female_xiaohe_uranus_bigtts` 创建，用户可在「角色与音色」里改。

### 提示词策略

- 只描述人物、商品与动作，不生成画面内文字、价格、认证、销量、功效结论或品牌标语。
- 人物外观严格参考人物图；商品严格参考商品图，不添加不存在的配件。
- 构图明确要求“半身近景、腰部以上、镜头与眼睛齐平、头顶/脸部/肩部完整入镜”，并把人物设为画面主体；商品只是手持道具，必须位于胸前或画面下三分之一，不能遮挡脸、眼睛或嘴。
- 三种展示方式对应不同动作，但都要求镜头稳定、真实电商短视频质感，并反复强调不要拉远成全身远景、不要裁掉头顶/眼睛/下巴。
- AI 人物定妆照同样要求头部和脸部完整入镜、脸部位于画面中央偏上，减少后续视频裁脸。
- AI 人物定妆照只生成人物，不生成商品，减少人物与商品结构互相污染。
- 台词由服务端在提交时追加，避免提示词里重复写台词或让模型自行发挥。

## 已知风险

- **口型同步尚未用真实 H3 付费调用验证**：需要用户用测试商品各生成一条 lipsync 与 post 样片。
- **商品保真有限**：生成式模型可能改变包装文字、纹理或细节；重要卖点仍需人工检查。
- **TTS 先决条件**：需要先在模型中心配置火山引擎语音渠道，否则只能创建分镜，不能合成配音。
- **AI 人物一致性**：参考模式能保持大致身份，但不同镜头之间仍可能有细微差异；本期只做单镜头。
- **生图与视频都产生费用**：弹窗只显示视频预估，人物定妆图按既有生图运行记录计费。

## 验证方法

开发侧（不调用付费接口）：

1. `npm test`：新增 `tests/creation-presenter.test.mjs`，覆盖入参校验、台词清洗、提示词组装与人物图提示词。
2. `npm run check`：语法检查。
3. `npm run build`：前端构建。
4. 使用本地夹具检查画布节点、连线、分镜追加与引用校验。

用户验收（需要测试商品）：

1. 先做一条 480P、5 秒、口型同步样片，确认人物、商品与口型。
2. 再做一条 480P、5 秒、后期配音样片，对比自然度与成本。
3. 确认后再决定默认配音方式，并把默认值调整写回本文与设置。
4. 若商品细节失真，优先增加商品参考图数量或调整提示词，而不是直接提高分辨率。
